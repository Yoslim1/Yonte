# Design System Constitution

## Purpose

Define what is globally consistent and what each feature may customize.

## Global laws

Shared tokens/patterns govern typography, color roles, spacing scale, navigation conventions, confirmation/destructive affordances, error language, accessibility baseline, and common component behavior.

## Feature freedom

Features may have unique layouts, specialized components, workflows, information architecture, and visual emphasis as long as global accessibility/security/interaction laws remain intact.

## Rules

- No parallel design system inside a feature.
- Destructive and security-sensitive actions use consistent risk communication.
- Shared tokens are consumed rather than copied as literals when possible.
- UI redesign must not require persistence/security refactors unless behavior genuinely demands them.
